# Project Retrospective

## Purpose

Convert a project archive into a traceable retrospective and reusable operating assets without rewriting uncertain history as fact.

## Required Inputs

- project root or asset manifest
- project identity, timeframe, role, and intended audience
- available source hierarchy: signed/approved records, project control files, dated status/decision records, working files, recollections
- confidentiality and career-publication boundary

Minimum viable evidence: dated project records, outcome/acceptance evidence, ownership evidence, and representative operating artifacts. If any are missing, continue with an evidence-gap report and confidence labels.

## Workflow

### 1. Asset and Evidence Map

Inventory files by type, date, delivery line, authority, and status. Detect duplicates and conflicting versions. Define `Fact / Inference / Claim / Gap` labels and cite sources.

### 2. Timeline and Outcome

Reconstruct phases, milestones, pivots, crises, decisions, acceptance, and residuals. Compare intended versus actual outcomes; do not equate activity volume with value.

### 3. PM Ownership and Career Assets

Map context, challenge, actions personally owned, collaboration boundaries, decisions influenced, artifacts created, outcomes, and evidence. Separate direct ownership, contribution, and team result. Produce a confidential full case and a disclosure-safe career version when requested.

### 4. Project Operating System

Extract source-of-truth architecture, meeting/decision cadence, roles, risk and escalation, review gates, versioning, evidence and acceptance, vendor control, and closeout. Mark proven patterns versus retrospective recommendations.

### 5. Efficiency Review

Identify repeated manual work, rework, wait states, duplicate sources, late decisions, unclear ownership, evidence debt, and AI-assisted leverage. Estimate only when inputs support it; otherwise use relative impact/confidence.

### 6. Workflow Audit

Inventory prompts, templates, checklists, meetings, decisions, risk reviews, acceptance, reporting, vendor feedback, and closeout. Rate:

- L0 one-off prompt
- L1 repeated prompt
- L2 stable workflow
- L3 skill-ready: reusable, explicit input, stable process, standard output, AI-executable, clear human boundary
- L4 existing implemented skill

For every L3/L4 item document Trigger, Input, Process, Rules, Output, Boundary, Failure Mode, and Required Context. Recommend Prompt/Template/Workflow when any skill gate fails.

### 7. Skill Action

Search existing project and installed skills before creating. Review L4 trigger fitness and workflow completeness. Create or update only L3/L4 skills authorized by the user. Validate structure and simulate at least one representative case. Keep an action table: workflow, maturity, evidence, action, path, readiness.

### 8. Consistency and Handoff

Cross-check timeline, metrics, ownership, outcome, and workflow maturity across all retrospective outputs. List unresolved contradictions and exact missing sources.

## Standard Outputs

1. Factbase: timeline and outcome
2. Career case study and PM ownership
3. Project Operating System and efficiency review
4. AI Workflow Audit
5. Project Skill Library
6. created/updated skill folders and acceptance result, when authorized
7. final Workflow → Maturity → Action table

## Rules

- Search before assuming; cite exact local paths for material claims.
- Preserve source files; write retrospective outputs separately.
- Use absolute dates and distinguish planned, reported, verified, and accepted.
- Never inflate personal ownership, quantified impact, or project success.
- Treat missing upstream outputs as a gap; reconstruct from first-party evidence when possible and label inference.
- Do not create skills for unstable judgment, unclear inputs, nonstandard outputs, or work requiring undelegated human authority.

## Boundary and Failure Handling

AI can discover, classify, synthesize, draft, cross-check, and implement authorized skills. Humans confirm confidential boundaries, personal ownership, disputed facts, strategic lessons, and consequential approvals. If the archive is too large, prioritize source-of-truth and dated control records, publish a coverage map, and leave lower-authority sources as sampled rather than implying exhaustive review.

## Acceptance Check

- all required output areas are present or explicitly blocked;
- material claims are traceable;
- ownership and outcome are not overstated;
- maturity ratings use the six gates consistently;
- every created skill has a realistic trigger, stable workflow, clear boundary, failure handling, and simulated acceptance evidence;
- cross-document contradictions are resolved or listed.
